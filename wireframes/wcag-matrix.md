# WCAG 2.1 AA Mapping Matrix: Freedom Park Library Portal

Ticket MD-2026-0143 | Part A wireframes (`landing.html`, `listing.html`, `booking.html`, `main.css`)

| # | Criterion (ID & Name) | Target component | Technical implementation | Verification strategy |
|---|---|---|---|---|
| 1 | **1.1.1 Non-text Content** (A) | Book covers, event images, team photos, header logo, search icon | Informative images get concise, specific `alt` text. Where a `<figcaption>` or heading already names the subject (book covers, team portraits, category illustrations), the image uses `alt=""` so it is not announced twice. The repeated footer logo also uses `alt=""`. The search button has visible text "Search" and no icon. | axe `image-alt` and `button-name` rules; NVDA browse mode (G key) to hear each graphic; confirm no empty button is announced. |
| 2 | **1.3.1 Info and Relationships** (A) | Landmarks, heading outline, booking form | `<header>`, `<nav aria-label="Main">`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>`. One `<h1>` per page, no skipped levels. Booking form uses `<fieldset>`/`<legend>` groups and `<label for>` on every control. | NVDA landmarks list (D) and headings list (H); W3C Nu HTML validator; axe `landmark-*`, `heading-order`, `label`. |
| 3 | **1.3.5 Identify Input Purpose** (AA) | Booking form: name, email, phone | `autocomplete="name"`, `autocomplete="email"`, `autocomplete="tel"`. | Inspect markup; browser autofill fills the three fields; axe `autocomplete-valid`. |
| 4 | **1.4.1 Use of Color** (A) | Links, current nav item, error state | Links are always underlined. Current page uses `aria-current="page"` plus bold and thicker underline. Error styling pairs red with a thicker border and a text message. | Greyscale/forced-colours emulation in DevTools; confirm every state is still distinguishable. |
| 5 | **1.4.3 Contrast (Minimum)** (AA) | All text | Palette chosen so every pairing is at least 5.4:1 for body text; ratios logged in the `main.css` header. Placeholder text also passes. | WebAIM Contrast Checker for each logged pairing; Lighthouse and axe `color-contrast`. |
| 6 | **1.4.10 Reflow** (AA) | Whole layout, card grid, form | Fluid CSS grid with `repeat(auto-fit, minmax(min(100%, 14rem), 1fr))`, `max-width: 100%` on images, correct viewport meta tag, aside stacks below 48rem. | Resize to 320 CSS px wide (or 400% zoom at 1280px) and confirm no horizontal scroll and no clipped content. |
| 7 | **1.4.11 Non-text Contrast** (AA) | Input borders, focus ring, fieldset borders | 2px `#4A5568` borders (7.5:1) and a `#2B6CB0` / white focus ring, both above 3:1. | WebAIM checker on each border and ring colour; visual check in Chrome. |
| 8 | **2.1.1 Keyboard** (A) | Nav, search form, filter `<details>`, booking form, footer links | Only native interactive elements (`a`, `button`, `input`, `select`, `textarea`, `details`), so Tab/Enter/Space work with no scripting. | Unplug the mouse and complete the booking form and search using only the keyboard; record the tab sequence in the README log. |
| 9 | **2.4.1 Bypass Blocks** (A) | Every page | "Skip to main content" link is the first focusable element and targets `<main id="main">`. It appears on focus. | Press Tab once on page load and confirm the link appears; press Enter and confirm focus moves into main content. |
| 10 | **2.4.2 Page Titled** (A) | Every page | Unique titles, for example "Room Reservation – Freedom Park Library". | Inspect each `<title>`; confirm no two pages share one. |
| 11 | **2.4.3 Focus Order** (A) | Every page | DOM order matches visual order; no positive `tabindex`; the skip link comes first. | Tab through each page and compare the order to the visual layout. |
| 12 | **2.4.4 Link Purpose (In Context)** (A) | Event "Register" links, footer social links | Each "Register" link carries visually hidden text naming the event. Footer links have working `href`s (`mailto:` for email). | NVDA links list (K / Insert+F7): every link is meaningful out of context. |
| 13 | **2.4.6 Headings and Labels** (AA) | All headings, form labels | Headings are never empty. Labels are specific ("Duration (minutes)", "Reason for reservation"). | NVDA headings list; manual read-through. |
| 14 | **2.4.7 Focus Visible** (AA) | All interactive controls | Global `:focus-visible { outline: 3px solid #2B6CB0; outline-offset: 2px; }` with a white inner ring on dark nav, footer and skip link. No `outline: none` is used anywhere. | Keyboard through every page and confirm a ring on each control; search the CSS for `outline: none` and `outline: 0` (expect none). |
| 15 | **3.1.1 Language of Page** (A) | Every page | `<html lang="en">`. | axe `html-has-lang`; NVDA reads in the correct voice. |
| 16 | **3.3.2 Labels or Instructions** (A) | Booking form | Visible labels, `.hint` text linked with `aria-describedby` (for example phone format, duration range), and "(required)" in label text. | NVDA forms mode: label, hint and required status are announced for each field. |
| 17 | **3.3.1 Error Identification / 3.3.3 Error Suggestion** (A/AA) **(Part B)** | React booking form | Wireframe uses native `required`/`pattern`. React adds `aria-invalid`, an `aria-describedby` error message, and an `aria-live` region plus a focus move to the first error. `[aria-invalid="true"]` is already styled in `main.css`. | Submit empty and invalid forms with NVDA running; confirm errors are announced and focus lands on the first invalid field. |
| 18 | **4.1.2 Name, Role, Value** (A) **(Part B)** | Filter accordion, tabs, dialogs in React | Wireframe uses native `<details>`. React replaces it with `<button aria-expanded aria-controls>` and `aria-pressed` toggles that update with state. | axe `aria-*` rules; inspect the accessibility tree while toggling. |
| 19 | **4.1.3 Status Messages** (AA) **(Part B)** | Search result count, form submission outcome | A persistent `aria-live="polite"` region announces "12 results found" and "Reservation confirmed". | NVDA: filter the list and confirm the count is spoken without moving focus. |

## Tooling used
axe DevTools, Lighthouse, W3C Nu HTML Checker, WebAIM Contrast Checker, NVDA with Firefox/Chrome, keyboard-only walkthrough.
