# Capstone-4
In a structured technical document (~400–600 words) located within the repository README.md, document the following engineering decisions:

## 1. Accessibility Trade-Off Analysis:
Detail three specific UX or architectural trade-offs made during development (e.g., balancing custom visual styling against native browser control behaviors, modal focus traps vs. smooth keyboard flows, or live region verbosity vs. silence). Explain the technical rationale for each decision.

## 2. Assistive Tech State Architecture:
Describe how React state management (hooks, context, or props) synchronizes with DOM accessibility tree attributes (such as aria-live, aria-expanded, aria-busy, and programmatic focus focus()).

## 3. Verification & Testing Audit:
Include automated testing results (axe-core or Lighthouse report demonstrating a 100% Accessibility score) alongside documented manual testing logs (detailing screen reader performance in NVDA, VoiceOver, or Orca, and manual keyboard tab-sequence verification).
